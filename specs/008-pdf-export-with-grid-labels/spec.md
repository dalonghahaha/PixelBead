# Feature 008 — PDF 导出 + 分块打印 ⭐

## Overview

用户最终动作是"打印出来照着拼"。当前竞品(国内小程序派、海外 App 派)把"格内印色号 PDF"当标配。PixelBead 003 已实现"符号图 + 预览图 + 色号用量"接口,但缺 **可打印 PDF** 这一终极闭环。

本 spec 提供 **零外部工具闭环**:
- 用户上传 → 生成图纸 → 一键导出 PDF → 打印 → 照着拼

PDF 内每格印色号 + 网格线 + 坐标轴 + 超大图自动分块 + 对位标记 + 可选符号图叠加。

⭐ 这是 Phase 1 核心 P0,**直接决定用户能否完成最终拼豆流程**。

不在本文范围:SVG 矢量导出(031 高级导出)、PDF 加水印(Phase 4 商业化)、PDF 编辑器(宪法 §5.2 不做)。

## User Scenarios & Testing

### Scenario 1 — 普通尺寸图纸导出单页 PDF
**角色**:上传一张中等尺寸照片(58×58 拼豆)生成图纸的用户
**流程**:
1. 在 `/patterns/{id}` 页点"导出 PDF"
2. 浏览器下载 1 个 PDF 文件
3. 打开 PDF:每格中心印有该格色号文字(或符号)
4. 网格线 + 坐标轴清晰(列 A-Z-AA-AZ...,行 1-N)
5. A4 横向打印 → 直接照着拼

**验收标准**:
- PDF 内每格中心印色号(文字或符号,与符号图一致)
- 网格线可见(线宽 ≥ 0.5pt)
- 坐标轴标注:列字母(行号 1-N,列 A-Z-AA-AZ...),轴标签在图纸外圈
- 字号 ≥ 6pt(打印后仍可读)
- A4 横向单页,无内容溢出
- 文件大小 < 2MB(58×58 估算)

### Scenario 2 — 超大图纸自动分块
**角色**:上传一张高分辨率照片,图纸尺寸 116×116(>A4 单页)
**流程**:
1. 导出 PDF,实际下载 1 个 PDF 包含 N 页(N = ceil(116/58)² ≈ 4 页)
2. 每页带对位标记(三角/箭头):左上、右上、左下、右下
3. 每页带拼接顺序编号(1/4, 2/4, 3/4, 3/4)
4. 拼接后图样完整无错位

**验收标准**:
- PDF 页数 = ceil(宽度/单页宽度) × ceil(高度/单页高度)
- 每页四对位标记位置一致
- 拼接后图纸完整,色号连续
- 每页有"第 X/Y 块"标识

### Scenario 3 — 自定义纸张大小
**角色**:有大尺寸打印机的用户,想用 A3 单页打印
**流程**:
1. 导出 PDF 前,在 UI 选择纸张大小(A4 / A3 / Letter / 自定义)
2. 选 A3 后,大图纸分块数显著减少
3. PDF 按 A3 比例输出

**验收标准**:
- UI 提供纸张选择下拉(A4 默认、A3、Letter)
- 自定义纸张:输入宽度 × 高度(mm 或 inch)
- 切换纸张后分块数正确重算
- PDF 实际纸张元数据正确

### Scenario 4 — 符号图叠加层(可选)
**角色**:对照拼豆习惯不同的用户
**流程**:
1. 导出 PDF 时,有"叠加符号图"勾选框(默认关闭)
2. 勾选后,PDF 每格中心既有色号又有符号图符号
3. 切换关闭,只显示色号

**验收标准**:
- 勾选框默认关闭(节省视觉)
- 勾选时,色号 + 符号并存,两不遮盖
- 切换状态影响本次导出(下次恢复默认)

### Scenario 5 — 批量下载分块 zip
**角色**:超大图纸分多页,用户想批量打印
**流程**:
1. 导出 PDF 时勾选"分块独立 + zip 打包"
2. 下载 1 个 zip 文件,内含 N 个 PDF(每块 1 个)+ 1 个 index.json(标注拼接顺序)
3. 用户解压后批量打印

**验收标准**:
- zip 内 N 个 PDF 与分块数一致
- index.json 含每块的坐标范围、拼接位置
- zip 文件名格式:`pixelbead-pattern-{id}-tiles.zip`

### Scenario 6 — PDF 与模式语言一致
**角色**:在英文模式下生成 + 导出
**流程**:
1. 当前 locale = en,导出 PDF
2. PDF 内坐标轴标签、色名标注、说明文字均为英文

**验收标准**:
- PDF 内所有文字跟随当前 locale(zh / en)
- 色名标注用 `name_en`(005 协同)
- 页眉/页脚/标题/说明均双语

## Functional Requirements

### FR-1: PDF 基础格式

- 输出格式:PDF 1.7(主流阅读器/打印机兼容)
- 默认纸张:A4 横向(297×210mm)
- 边距:上下左右各 10mm(预留打印边距)
- 网格占据纸张内剩余空间

### FR-2: 每格色号/符号标注

- 每格中心印色号文字(优先)或符号图符号(可选)
- 字号自适应:格子越小字号越小,但 ≥ 6pt(可读性)
- 颜色:深色格用白字,浅色格用黑字(自动对比)
- 文字字体:内置等宽字体(无外部字体依赖)
- 字符:色号(如 "H1")或符号(如 ◆)(符号集与符号图一致)

### FR-3: 网格线 + 坐标轴

- 网格线:每格之间画 1 条细线(线宽 0.5pt,黑色)
- 粗网格:每 10 格画 1 条粗线(线宽 1pt,深灰)
- 坐标轴标签:
  - 列:从 A 开始,A-Z 后接 AA-AZ,BA-BZ...
  - 行:从 1 开始,1, 2, 3...
  - 标签位置:图纸外圈(上方为列,左侧为行)
  - 字体大小:8pt(清晰可读)

### FR-4: 超大图纸自动分块

- 触发条件:图纸尺寸 > 当前纸张可容纳的格子数
- 分块算法:每块 = 当前纸张可容纳的最大格子数(留 5% 余量)
- 每页结构:
  - 该块的图样内容
  - 该块的全局坐标范围标注(如 "A1 - Z29")
  - 四角对位标记(三角/箭头):
    - 左上:▲(实心)
    - 右上:▶
    - 左下:◀
    - 右下:▼
  - 页码标识:"第 X / Y 块"(居中底部)
- 拼接顺序:从左到右、从上到下

### FR-5: 自定义纸张大小

- UI 选项(下拉):
  - A4 横向(默认,297×210mm)
  - A4 纵向
  - A3 横向(420×297mm)
  - Letter 横向(279.4×215.9mm)
- 自定义:宽度(mm/inch)、高度(mm/inch)
- 切换纸张后实时预览分块数变化

### FR-6: 符号图叠加层

- UI 选项:勾选框"叠加符号图"(默认关闭)
- 开启时:每格同时显示色号 + 符号
- 关闭时:仅色号(简洁)
- 状态:本次导出有效,下次恢复默认

### FR-7: 分块独立 + zip 打包

- UI 选项:勾选框"分块独立 zip"(默认关闭)
- 关闭时:导出 1 个多页 PDF
- 开启时:导出 1 个 zip,内含:
  - `tile-001.pdf` `tile-002.pdf` ...
  - `index.json`:`{ pattern_id, total_tiles, tiles: [{ index, row_range, col_range }] }`
  - `README.txt`:拼接说明
- 文件命名:`pixelbead-pattern-{id}-tiles.zip` 或 `pixelbead-pattern-{id}.pdf`

### FR-8: 文件大小控制

- 58×58 图纸 PDF < 2MB
- 116×116 图纸 PDF < 8MB(或分块后单块 < 2MB)
- 优化策略:矢量线条 + 文本嵌入,图片仅用于符号叠加层(如启用)

### FR-9: 错误处理

- 图纸生成中 → 提示"图纸尚未就绪"
- 图纸被删除 → 提示"图纸不存在"
- PDF 渲染失败 → 提示 + Sentry 上报

### FR-10: 国际化

- PDF 内文字(页眉、页脚、色名、说明)跟随 locale
- 005 协同,自动获取 `name_en` / `name_zh`

## Success Criteria

### 定量

- PDF 导出成功率 ≥ 99%(7 天窗口,基于 006 埋点 `pb_export_pdf`)
- 58×58 图纸 PDF 大小 < 2MB
- 116×116 图纸 PDF 大小 < 8MB(或单块 < 2MB)
- 每格色号字号 ≥ 6pt(打印 300dpi 仍可读)
- 网格线 100% 正确(无缺失、无错位)
- 分块拼接后图纸完整(自动化测试:对比原图分块 + 拼接,差异 < 1%)
- 坐标轴标注 100% 正确(A-Z-AA-AZ 序列无重复无跳)

### 定性

- 用户拿到 PDF 后无需任何额外处理,直接打印照拼
- 大图纸分块拼接无歧义(对位标记 + 页码足够)
- 色号 + 符号(若叠加)打印后肉眼一眼可分

## Key Entities

- **PdfExportRequest**:`{ pattern_id, paper_size, locale, overlay_symbols, tile_zip }`
- **PdfTile**:`{ index, row_range, col_range, file_blob }`
- **PdfManifest**(zip 内):`{ pattern_id, total_tiles, tiles: [...], locale }`

## Assumptions

- 003 已提供 `GET /patterns/{id}/symbol` 和 `GET /patterns/{id}/preview` 端点
- 003 已提供图纸网格数据 API(`GET /patterns/{id}/grid` 需新增或扩展)
- 005 完成后 `name_en` / `name_zh` 可用
- 006 完成后埋点 `pb_export_pdf` 可记录成功/失败

## Out of Scope

- **SVG 矢量导出** → 031 高级导出
- **PDF 编辑器 / 二次编辑** → 宪法 §5.2 不做
- **PDF 加水印** → Phase 4 商业化
- **PDF 加密 / 权限控制** → 不需要,本就是用户自己生成的内容
- **服务端渲染 PDF** → 前端实现优先(无 IO 压力);大文件场景再评估
- **3D 预览集成** → 宪法 §5.2 不做
- **PDF 全文翻译** → 仅翻译标签 + 色名,不翻译图纸本体

## Clarifications

### Session 2026-09-20

- Q: PDF 在前端生成还是后端生成? → A: 前端优先 — 现有竞品基本前端实现,无需后端 IO,降低服务器成本;大图(>200×200)再评估服务端方案。
- Q: 色号 vs 符号,默认显示哪个? → A: 色号优先 — 大部分用户习惯看色号对照表;符号作为可选叠加层(FR-6)。
- Q: 分块触发条件是什么? → A: 当前纸张容纳不下时自动分块 — 58×58 在 A4 横向下不需分块;116×116 自动 2×2=4 块。
- Q: 对位标记用什么形状? → A: 三角箭头(▲▶◀▼) — 简单清晰,占用空间小,黑白打印后仍可辨。
- Q: PDF 内坐标轴用字母还是数字? → A: 字母(A-Z-AA-AZ)+ 数字(行 1-N) — 国内外主流习惯,Excel 风格。
- Q: 008 要不要把 SVG 矢量导出一起做了? → A: 不做 — 矢量导出是 031 高级导出的范围,本 spec 仅 PDF。SVG 涉及矢量库 + 字体 + 浏览器兼容性,投入大。
- Q: 008 要不要做服务端 PDF 渲染备份? → A: 不做 MVP — 前端方案稳定后再评估;前端失败有 Sentry 监控,失败率 < 1% 即可。
