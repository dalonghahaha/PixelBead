# Feature 009 — 拼豆规格选择

## Overview

拼豆有两种主流规格:
- **2.6mm(Mini / 迷你)**:MARD 主流小颗粒,适合精细图案,底板常见 29×29 / 58×58
- **5mm(Midi / 大颗)**:Midi 大颗粒,适合儿童/低视力玩家,底板常见 29×29 / 58×58

当前 PixelBead 003 默认使用单一规格(实际为 Mini),用户无法切换。这导致:
- 大颗拼豆玩家用 PixelBead 生成的图纸拼出来"格子太大、太稀疏",体验错位
- 用户需手动换算格子数到对应底板(29×29 Mini → 16×16 Midi),心智成本高
- 中老年/儿童玩家(主流 Midi 群体)被排除

本 spec 提供 **显式规格选择 + 底板尺寸提示**,让用户选择适合自己豆 + 底板的尺寸。

不在本文范围:立体拼豆(宪法 §5.2 不做)、第三方非标准规格豆(非主流市场,不做)、AI 智能推荐规格(宪法 §5.2 不做)。

## User Scenarios & Testing

### Scenario 1 — Mini 拼豆玩家
**角色**:用 MARD Mini(2.6mm)豆 + 29×29 底板的玩家
**流程**:
1. 上传图片
2. 在生成参数面板看到"拼豆规格"选项,默认"Mini (2.6mm)"
3. 看到底板提示"29×29 底板可容纳 29×29 格子;58×58 底板可容纳 58×58 格子"
4. 选择 Mini 后生成图纸,格子大小适合 Mini 豆

**验收标准**:
- 默认规格 = Mini(2.6mm)(保持现状,无破坏性变更)
- UI 显式标注 "Mini (2.6mm)" 或 "迷你 (2.6mm)"
- 底板尺寸提示清晰(基于图纸格子数推算)
- 切换规格后,生成图纸的实际格子大小与所选规格匹配

### Scenario 2 — Midi 拼豆玩家
**角色**:用 Midi(5mm)豆的玩家(中老年/儿童主流)
**流程**:
1. 上传图片
2. 切换规格到 "Midi (5mm)"
3. 看到底板提示"Midi 拼豆通常用 16×16 底板"
4. 生成图纸,格子大小适合 Midi 豆

**验收标准**:
- UI 提供 Midi 选项,标注 "Midi (5mm)" 或 "大颗 (5mm)"
- 切换后底板尺寸提示重新计算(Midi 格子数比 Mini 少)
- 生成参数正确传递给后端

### Scenario 3 — 不知道规格的用户
**角色**:第一次玩拼豆,不知道 Mini / Midi 区别的新手
**流程**:
1. 进入生成页,看到规格选择
2. 鼠标悬停或点击"?"图标
3. 看到简短说明:"Mini 2.6mm 主流;Midi 5mm 大颗,适合儿童/低视力"
4. 做出选择

**验收标准**:
- 规格选项旁有"?"或 tooltip 说明
- 说明文字简洁(< 50 字),不强制阅读
- 默认 Mini(降低新用户决策成本)

### Scenario 4 — 切换后生成参数生效
**角色**:先选 Mini 看预览,再切 Midi
**流程**:
1. 选 Mini,生成 58×58 图纸
2. 切换到 Midi
3. 重新生成:图纸格子数减少(因 Midi 在同样底板上占更少格子)
4. PDF 导出(008 协同)格子大小与 Midi 匹配

**验收标准**:
- 切换规格后,生成参数实时更新
- 后端接收规格参数,正确计算格子大小
- 重新生成耗时合理(< 5s)

## Functional Requirements

### FR-1: 规格选项

- UI 提供 2 个选项:
  - **Mini (2.6mm)** — 默认,主流
  - **Midi (5mm)** — 大颗
- 选项展示:分段控件 / 单选按钮 / 下拉(三选一,UI 决策)
- 每选项标注:规格名 + 直径(mm)+ 简短说明
- 默认 = Mini(保持现状,无破坏性)

### FR-2: 规格说明

- 每选项旁有"?"图标或 tooltip
- 说明文字包含:
  - Mini:"主流小颗粒,适合精细图案(2.6mm)"
  - Midi:"大颗,适合儿童/低视力(5mm)"
- 帮助链接(可选):指向外部参考图或文档

### FR-3: 底板尺寸提示

- 根据所选规格 + 图纸格子数,计算并提示底板大小
- 提示格式:
  - "29×29 底板可容纳 29×29 格子"
  - "58×58 底板可容纳 58×58 格子"
- Mini 与 Midi 同样格子数下,所需底板尺寸不同(同底板下 Midi 容纳更少格子)
- 提示需基于实际图纸尺寸,不得固定文案

### FR-4: 规格参数传递

- 规格参数(`bead_size: "mini" | "midi"`)传给生成 API
- 后端接收并正确处理(格子大小按规格调整)
- 现有 API 兼容性:旧调用方不传时默认 Mini

### FR-5: 与 003 / 008 协同

- 003 生成接口扩展支持 `bead_size` 参数
- 008 PDF 导出:格子大小与所选规格匹配(不需特别处理,只需后端参数正确)
- 005 协同:规格名/说明文字跟随 locale

### FR-6: 与 010 异步协同

- 异步队列任务携带 `bead_size` 参数
- 任务完成后,图纸元数据含 `bead_size` 字段
- 前端轮询时返回规格信息

## Success Criteria

### 定量

- UI 提供 Mini + Midi 2 个选项,默认 Mini
- 切换规格后,生成图纸格子大小与规格匹配(自动化校验)
- 底板尺寸提示准确(基于格子数 + 规格计算)
- tooltip/help 链接在 100% 规格选项旁存在
- 现有未指定规格的 API 调用,默认 Mini 不报错

### 定性

- 用户能清楚区分 Mini 和 Midi(说明文字 + 图标)
- 大颗拼豆玩家切换后,生成图纸体验明显提升
- 新手不被规格选择劝退(默认 Mini + tooltip)

## Key Entities

- **BeadSize**:枚举值 `mini` (2.6mm) / `midi` (5mm)
- **GenerationParams**(扩展现有):新增 `bead_size: BeadSize`
- **PatternMetadata**(扩展现有):新增 `bead_size: BeadSize`(便于回显)

## Assumptions

- 003 当前生成逻辑未严格区分规格,默认按 Mini 处理
- 后端 pypindou 算法支持规格参数(或可扩展)
- 用户偏好:国内 Mini 为主流,Midi 用户约 20-30%(基于公开市场数据)
- 底板尺寸标准:29×29 / 58×58 是 Mini/Midi 通用

## Out of Scope

- **立体拼豆** → 宪法 §5.2 不做
- **第三方非标准规格豆**(1.4mm / 8mm) → 非主流市场
- **AI 智能规格推荐** → 宪法 §5.2 不做
- **多规格混拼**(一面 Mini 一面 Midi) → 不现实,不做
- **异形底板**(圆形/心形) → 留作 Phase 3 打印预设(016)
- **底板购买链接** → 宪法 §5.1 不做电商导流
- **规格历史偏好**(记住用户上次选择) → 留作体验优化,非 MVP

## Clarifications

### Session 2026-09-20

- Q: 默认规格是 Mini 还是 Midi? → A: Mini — 国内基盘,Mini 主流,默认降低破坏性。
- Q: 规格选项 UI 用什么控件? → A: 分段控件 / 单选按钮 — 更直观,比下拉更突出选项;具体实现细节 plan 阶段定。
- Q: 底板尺寸提示要不要算"格子数 vs 底板数"的强约束? → A: 弱约束(提示性) — 仅提示"X×Y 底板可容纳 N×N 格子",不强校验;用户可能拼跨多个底板。
- Q: 009 要不要加规格历史偏好? → A: 不做 MVP — 留作体验优化,先让规格选择本身可用。
- Q: Midi 玩家在底板不足时怎么提示? → A: 仅提示"底板尺寸",不强引导购买 — 不引入电商导流。
- Q: 009 要不要把规格影响 PDF 导出(008)的字号 / 格子大小也详细定义? → A: 不定义 — 008 已有逻辑,只需规格参数正确传递,字号自适应已在 008 FR-2 处理。
